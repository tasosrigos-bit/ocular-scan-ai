# Part 2 — Retrieval-Augmented Narrative Layer

Part 1 produces a disease label, a calibrated confidence, and a rule-based triage
urgency. Part 2 adds a **narrative explanation for the clinician**, generated by a
language model, grounded in a small curated knowledge base, with a citation for
every clinical claim.

The hard constraint: **the language model never makes or influences the
diagnostic or urgency decision.** That stays entirely with Part 1's rule engine.
The model's only job is to explain, and an automated check discards its output if
it strays.

## 1. Architecture

```
Part 1 (unchanged)                         Part 2 (new)
──────────────────                         ────────────
OCT image                                  knowledge_base/*.md   (6 entries, in git)
   │                                            │  ingest: split on ## headings
   ▼                                            ▼
DenseNet-121 → calibrated probs            Passages  (amd#overview, cnv#referral, …)
   │                                            │  embed (bge-small-en-v1.5)
   ▼                                            ▼
CDSRuleEngine → Recommendation             FAISS flat index  (cached on disk)
   (class, confidence, urgency,                 │
    differential)                               │
   │            │                               │
   │            └────► decision-aware retrieval ◄── predicted class + differential
   │                          │
   │                          ▼
   │                 retrieved passages (ids + text + sources)
   │                          │
   └────────────► RAG narrator (local Qwen2.5-3B, temperature 0)
                          │   system prompt: the decision is FIXED;
                          │   cite every factual sentence with [passage#id]
                          ▼
                  draft narrative
                          │
                          ▼
                  verify.py ── citations resolve? asserts a different class?
                     │ pass        downgrades the fixed triage?
                     │                    │ fail
                     ▼                    ▼
              grounded narrative    Part 1's templated narrative (fallback)
                     │
                     ▼
        build_report(...) → report:
          impression / triage  = verbatim from Recommendation (never touched)
          narrative_rag        = the grounded narrative
          citations            = [{id, label, sources, snippet}]
          narrator_meta        = {verified, flags, model, retrieved_ids, raw_text}
```

**Code** (`src/oct_cds/rag/`): `ingest` → `embed` → `index` → `retrieve` →
`llm` → `prompt` → `narrator` → `verify` → `cache`. Entry point:
`rag_narrate.py` (Hydra, `paths=kaggle`). One Part 1 file changed —
`cds/report.py` gained an optional `narrator=` argument that only *adds* fields.

### Retrieval is decision-aware

Retrieval never re-decides anything. Given `Recommendation.predicted_class` (from
the rule engine), the narrator pulls:

1. **deterministically** — every passage of the knowledge-base entry that
   `covers` the predicted class;
2. **deterministically** — the "Model Behavior Note" passage for the predicted
   class and for each differential class (this project's own validation evidence
   for that class);
3. **semantically** — top-*k* passages for a query built from the differential.

The predicted class is used only as a lookup key.

### Model choice

Default backend is **local Qwen2.5-3B-Instruct** via `transformers`, temperature
0. It runs on the same Kaggle GPU as Part 1, needs no API key (so the result is
reproducible by anyone with the repo), and keeps every input on the machine.
`rag.llm.backend=anthropic` swaps in the Anthropic API behind the identical
interface — a config change, no code change — but validation showed the local
model is sufficient (see §4).

Embeddings: `BAAI/bge-small-en-v1.5` (384-d, CPU). Vector store: `faiss-cpu`, a
brute-force flat index over ~30 passages, cached to `knowledge_base/.index/`.

## 2. Knowledge base — sourcing and licensing

The narrator may ground its explanations **only** in `knowledge_base/*.md`. There
is no live internet retrieval.

Every entry is built **only** from:

- **NEI (U.S. National Eye Institute)** material — public domain (U.S. federal
  government work); or
- **open-access articles under a licence that permits derivative works** —
  CC-BY, CC-BY-SA.

Explicitly excluded: **AAO Preferred Practice Patterns** and **EyeWiki**, whose
terms restrict reuse "in an artificial intelligence program"; and **StatPearls**
(CC-BY-NC-ND — no derivatives). Part 1's earlier placeholder citations referenced
AAO PPPs; those were removed (`cds/guideline_refs.py` now returns nothing) and
citations will be sourced from this knowledge base instead.

All entry text is paraphrased, never copied verbatim. Provenance is recorded per
entry in [`knowledge_base/SOURCES.md`](knowledge_base/SOURCES.md).

| Entry | Covers (Part 1 classes) | Sources |
|---|---|---|
| `amd.md` | AMD, Drusen | NEI — Age-Related Macular Degeneration; NEI CAPT trial |
| `cnv.md` | CNV | NEI — Age-Related Macular Degeneration |
| `dme.md` | DME | NEI — Macular Edema |
| `dr.md` | DR | NEI — Diabetic Retinopathy |
| `macular_hole.md` | Macular Hole | NEI — Macular Hole |
| `csr.md` | CSR | Varghese et al., *Cureus* 2022 (CC-BY) |

`Normal` has no entry — a `Normal` prediction skips the narrator entirely.
Each entry also carries a **Model Behavior Note** section summarising how this
classifier performed for that class in internal and external validation, so the
narrative can attach a grounded caveat about model reliability.

## 3. Structural safety guardrails

The "the model never decides" constraint is enforced by construction, not by
prompt wording alone.

| Guardrail | Mechanism |
|---|---|
| **Decision freeze** | The `Recommendation` is computed by Part 1 and passed to the narrator read-only. The narrator never imports the rule engine or the classifier. |
| **Output quarantine** | The report's `impression`, `differential`, and `triage` are copied verbatim from the `Recommendation`. The model's text lands only in a separate `narrative_rag` field. The plain `narrative` is always Part 1's templated text. |
| **Grounding required** | The system prompt forbids outside facts and requires a `[passage#id]` citation on every factual sentence, using only the retrieved ids. |
| **`verify.py` — hard failures → fallback** | A citation that does not resolve to a retrieved passage; no citation at all; the narrative asserting a *different* predicted class as the finding; the narrative *downgrading* the triage relative to the fixed urgency (e.g. "no referral is needed" when the decision is urgent — the dangerous direction). Any of these discards the narrative and the report falls back to Part 1's templated text. |
| **Skip, don't guess** | `Normal`, abstained, and out-of-distribution cases never reach the model — they pass straight through Part 1's plain output. |
| **One-shot citation retry** | If the *only* fault is a missing or malformed citation, the narrator re-asks once with the rejection reason appended. **It never retries a safety violation** — a wrong-class assertion or a triage downgrade fails immediately. Successful retries are recorded (`took 2 attempts`). |
| **Determinism** | Temperature 0 plus an on-disk cache keyed by `(recommendation, kb_version, model, retrieved ids)` — the same case yields the same narrative across runs. |

## 4. Validation

Run over the 37-scan OPTOPOL REVO clinic set (`rag_narrate.py paths=kaggle
rag_run.split=external_test`), local Qwen2.5-3B backend:

| Outcome | n | |
|---|---|---|
| **Verified** | **15 / 15 eligible (100%)** | 12 accepted first-shot, 3 after one citation retry |
| Fallback to Part 1 template | 0 | no narrative failed verification |
| Unresolved citations | 0 | every cited id resolved to a retrieved passage |
| Skipped — predicted `Normal` | 16 | passthrough to Part 1's "no pathology" output |
| Skipped — model abstained | 6 | no class to ground on |
| **Total** | **37** | |

Every narrative that was shown carried resolvable citations, correctly framed the
Model Behavior Note passages as past validation rather than statements about the
patient, and left the fixed impression and triage untouched. The local 3B model
was sufficient; the Anthropic backend was not needed.

### Worked example — `CNV__p0.png` (real OPTOPOL REVO clinic scan)

**Part 1 decision (frozen, passed through unchanged):**

| | |
|---|---|
| Impression | **CNV**, 97.68% calibrated confidence |
| Triage | **urgent** — "Expedite specialist referral (24–72h)" |

**Generated narrative** (`narrative_rag`, verbatim — citations shown inline):

> The OCT scan shows choroidal neovascularization (CNV), a condition characterized
> by the growth of abnormal blood vessels beneath the retina, which can lead to
> rapid vision loss `[cnv#overview]`. This finding aligns with the model behavior
> note indicating strong performance on CNV classification with 93.4% sensitivity
> and 88.1% precision `[cnv#model-behavior-note]`, though the external validation
> sample size was limited to just one case `[cnv#model-behavior-note]`. Given the
> high model confidence (98%) and the differential diagnosis suggesting CNV at
> 98%, central serous retinopathy (CSR) at 1%, and drusen at 0%, urgent referral
> is recommended due to the active, vision-threatening nature of CNV
> `[cnv#referral]`. Specialist review is reasonable given the narrow window for
> effective treatment and the significant symptoms such as central blurry vision
> and wavy lines `[cnv#symptoms]`.

**Citations** — 4, all resolved against `knowledge_base/cnv.md`, all NEI (public
domain): `cnv#overview`, `cnv#model-behavior-note`, `cnv#referral`, `cnv#symptoms`.

**Verification:** `verified: true`, `fallback_used: false`, `flags: []` — passed
on the first attempt, no citation retry needed. (Three of the 15 verified cases
did need the one-shot retry to add citations to otherwise-sound text; none
required more than one.)

Note that the narrative restates the urgency ("urgent referral is recommended")
by citing `cnv#referral`, which describes CNV in general as warranting urgent
referral. This is consistent with — not a substitute for — Part 1's fixed
`urgent` triage; `verify.py` only rejects a narrative that *contradicts* the
fixed decision (asserts a different class, or downgrades the urgency).

## 5. Running Part 2

```bash
pip install -e ".[rag]"                 # local backend
# pip install -e ".[rag-api]"           # only if using rag.llm.backend=anthropic

python rag_narrate.py paths=kaggle rag.llm.backend=stub          # offline sanity check
python rag_narrate.py paths=kaggle rag_run.split=external_test   # the 37 clinic scans
python rag_narrate.py paths=kaggle rag_run.split=test            # OCT-C8 test set
```

Outputs to `<output_dir>/rag/`: `narratives_<split>.jsonl` (one full report per
case), `summary_<split>.json` (outcome counts, flag counts), and
`rejected_<split>.txt` (raw model output for any rejected/flagged case, for
prompt debugging). [`notebooks/demo_part2.ipynb`](notebooks/demo_part2.ipynb)
walks the knowledge base, a narrated case, and the verification summary.

## 6. Limitations specific to Part 2

- The knowledge base is 6 short entries. It covers the disease-level facts and
  this project's validation evidence, but not (yet) the OCT-appearance detail
  that would let the narrative connect a prediction to a specific visual finding.
- The narrative is only as good as the retrieved passages; retrieval quality on a
  ~30-passage corpus was not formally evaluated beyond confirming the
  predicted-class entry is always retrieved.
- `verify.py`'s contradiction checks are heuristic (regex over urgency and
  class phrases). They are deliberately conservative — biased toward false
  rejection (safe: fall back to the template) over false acceptance.
- All validation is retrospective on 37 scans. See [LIMITATIONS.md](LIMITATIONS.md).
